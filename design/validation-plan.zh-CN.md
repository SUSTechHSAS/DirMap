# 验证、实施门槛与有限空间操作

> 这是前一阶段的验证计划。当前已有应用及真实图检查，见 [实施状态](../IMPLEMENTATION_STATUS.md) 与 [当前检查汇总](../evidence/runtime/verification-summary.json)。以下 G0–G9 没有因开发版测试通过而自动完成。

对应 [实施方案](implementation-plan.zh-CN.md)。本文件区分：本次已经执行的方案验证，实施阶段需要的真实验收。没有把后者打勾冒充完成。

## 1. 本次可复现验证

在项目根目录运行，使用已有 Python 和 PDF 文本工具，不安装依赖：

```bash
python3 -B tools/inspect_inputs.py --output evidence/input-manifest.json
python3 -B tools/design_probe.py --output evidence/design-probe.json
```

第一个脚本读取文件哈希、JPEG/PNG 头部、PDF 元数据与文字层，不解码像素。第二个脚本只处理合成坐标/网格，不接触原始图文件；固定数据、无网络、无随机种子依赖，失败返回非零退出码。`-B` 避免生成 pycache。

已经得到五文件元数据清单与 **21/21 合成检查通过** 的 JSON。脚本没有模拟 OpenCV 识别、真实 GNSS、浏览器权限或大规模 OR-Tools，不能据此声称应用已经工作。接口类型也不等价于后端实现。

## 2. 实图与现场基准怎样建立

1. 先确认三张地图对应的校区、边界、比例尺、日期、实际图例版本，分清图幅、图例、标题和课程叠印。原文件和 SHA-256 固定，任何裁切/纠偏都用派生记录。
2. 每图准备常规 12–20 个拟合地物点，至少 8 个分布内点；另有至少 10 个不参与拟合/调参的独立核查位置。记录地物类型、原像素、参考坐标、来源精度、所属空间分区。禁止只随机抽相邻像素当独立空间验证。
3. 教师/测图者建立真实控制点清单、必到规则、可通/禁行线面、门洞、楼梯/桥隧层级的基准。细窄门、拐角、图边、稠密建筑区要纳入，不能只测容易的大路。
4. 数据少时，对算法调参用开发区/交叉验证，留出独立空间区域和最终核查点；共享相同底图或相邻裁片不能同时当训练和“新图”泛化证据。只有三图，不给出面向任意定向图的泛化率承诺。
5. 外场优先走每条计划经过的通道、门洞和多层连接；记录日期及临时关闭情况。地图年代不代表今天门一定开放。纸面几何误差与手机 GNSS 误差分别测量，不能用漂移 GPS 当高精度参照。

在当前“避免直接读图”的约束下，这些实图标注与图像处理尚未执行。实施期可以让远端程序处理图像，只把坐标、统计和必要的局部问题清单回传；需要视觉确认时再按可用的可靠读图方式开展。

## 3. 各功能的发布门槛

以下数值是首期课堂工程目标，需在 P0 明确参照测量精度后冻结。它们不是已经达到的结果，也不能替代狭窄通道的语义判断。

| 门槛 | 方法 | 合格条件 / 失败处理 |
| --- | --- | --- |
| G0 坐标链 | 已知 WGS84 点经官方转换，与已知 GCJ02 输入各走一条链；检查 x/y、lng/lat、单位、重复转换 | 同一位置一致；转换失败不绘制伪准确位置；任何混用基准立即停止发布 |
| G1 配准 | 三图逐张测独立点的中位数、P95、最大米制误差及 n；另查目标附近 | 初值 median≤3 m、P95≤8 m、max≤12 m；不达标改参照/补锚点/重选局部模型；不只展示拟合残差 |
| G2 形变与叠层 | 查三角形翻折、重叠、外推区、接缝与原像素反算；至少四角和内部点 | 折叠/重叠为 0；目标在有效域；图像、点、线使用同一变换；三图冲突可追溯 |
| G3 目标识别 | 对完整目标清单比对中心与编号；记录原始自动 precision/recall、逐图误差/修正次数 | 自动识别初值 precision/recall≥95%，同时报告小样本计数；课堂发布必到点清单 100% 对齐，无遗漏/重复/编号错配；人工修正率单列，不冒充自动成功 |
| G4 通行识别 | 对禁行线面、窄门、合法开放区抽样并查所有拟用路线；按区域统计分类与拓扑 | 发布图危险误开放为 0，所有实际使用门洞现场确认；可通行区域连通召回初值≥95%；未知边不加入正式路线，记录造成的不可达而不悄悄退化成直线 |
| G5 最短路与队伍 | 小规模用独立穷举/DP；真实图测 1/2/5/10 队及三种模式，含墙、门、断图、不同速度、起终点与时限 | 必到覆盖与顺序正确；每条输出线可展开到合法边；OPTIMAL 必须有证明，TIMEOUT 与 INFEASIBLE 区分；修改围墙/门后旧缓存失效 |
| G6 拥堵排程 | 同时/错峰、小容量、大队、小队、无可用时窗；检查完整边的占用时间线 | 不超容量；人数影响服务/通过时间正确；有限候选集的最优范围明确；未建立资源模型时不能展示“已避拥堵” |
| G7 手机方向 | iOS Safari 与 Android Chrome 至少各一台，记录机型/OS/浏览器版本；横竖屏、四方位、倾斜、走停、359↔1、拒绝权限、恢复页面 | 开阔地正常姿态方向误差中位≤10°、P95≤20°、响应≤500 ms；无过北整圈旋转；无罗盘/强磁干扰时提示和回退正确；GPS 运动方向不冒充手机指向 |
| G8 定位导航闭环 | 真机走完整短课程，核对目标、下一点、当前位置与障碍关系；分别测试转换来源与弱网 | 目标可找到、路线合法；偏航重规划遵守未完成点规则；定位误差圈和数据时间真实；未知位置不吸附穿墙 |
| G9 性能与空间 | 在记录配置的远端机器测预处理、出图、求解、手机刷新、峰值 RSS 和磁盘 | 目标：单图备课预处理≤120 s；30 点/10 队快速可行解≤5 s、精确模式预算30 s后如实给状态；手机≥30 fps；2 CPU/4 GB worker 初始中间文件与缓存限额内运行 |

G7 失败时在同一 UI 下实现原生传感器适配并重测，不能把学生永久切到手动旋转当成“朝向跟随已实现”。G1/G3/G4 的自动分支未达标时继续改善参考/分辨率/识别，不以全部手工绘制替换自动化验收。

G9 的快解预算与精确最优证明是两件事：超过预算并不表示算法没有可行解，30 s 也不是任意规模得到最优解的保证。计时包括当前测试定义的前置矩阵/缓存状态，必须分别报冷启动与热缓存。

## 4. 失败场景必须可解释

| 情况 | 正确结果 |
| --- | --- |
| 没有地理参考、锚点共线、在同一角落密集 | `NEEDS_REVIEW`，列缺少的覆盖区域/点对；不从图片中心猜经纬度 |
| 目标在锚点凸包外 | 明确未标定范围；补充参照后生成新版本 |
| OSM 缺少校园小路 | 对几何参照单独评估；图像/现场确认后构图，不用 OSM 空白断言不能通行 |
| 目标圈盖住墙、图例区有很多圆、控制点 OCR 重复 | 候选与歧义保留，发布清单核验前不自动丢点或新增打点 |
| 围墙有假缺口、桥上下同坐标、目标在墙另一面 | 无合法连接则拒绝，不能靠“最近点”跨墙/跨层 |
| split_coverage 被误当 all_visit | 逐队检查 coverage 矩阵，发现每队漏点即失败 |
| 解算超时且无路线 | `TIMEOUT_NO_SOLUTION`，保留模型、预算和任务；不是 `INFEASIBLE` |
| 找到可行路线但无下界/证明 | `FEASIBLE`，gap=null；不显示“最优率100%” |
| 罗盘相对角、空值/NaN、失效时间戳、位置静止漂移 | 不更新地图朝向，使用明确的可用回退或保留可靠方向 |
| 学生地图拖动、转屏、挂起恢复 | 跟随状态正确；恢复后弃旧样本，不与用户手势争抢相机 |
| 图或门状态改变 | 新 graphHash、旧路线失效、重新计算未完成部分 |

## 5. Codespace 验证路径（本次未执行远端操作）

本次标准库检查已足够验证方案中的关键数学性质，无需安装大包或启动远端机器。后续图像/浏览器/OR-Tools 测试优先使用已有 Codespace。命令语法依据本机 gh 帮助与 [S12](../evidence/sources.md) 核验；以下需要把占位名字替换成已有的 Codespace。

```bash
gh codespace list --json name,state,repository
DIRMAP_CS='已有的-codespace-name'
gh codespace ssh -c "$DIRMAP_CS" -- 'mkdir -p /tmp/dirmap-plan /tmp/dirmap-results'
gh codespace cp -c "$DIRMAP_CS" -r ./tools remote:/tmp/dirmap-plan/
gh codespace ssh -c "$DIRMAP_CS" -- 'python3 -B /tmp/dirmap-plan/tools/design_probe.py --output /tmp/dirmap-results/design-probe.json'
gh codespace cp -c "$DIRMAP_CS" remote:/tmp/dirmap-results/design-probe.json ./evidence/design-probe.remote.json
```

这段命令只是复跑当前小探针，不是完整三图识别命令。真正开始 P0/P1 后，在远端项目专用工作目录准备 Python 3.12 虚拟环境和依赖锁，按需要上传这五个源文件，核对 SHA-256；单图串行处理，图片结果留远端，只拉回统计、控制点、图数据与小型报告。不给本机装 Docker、下载模型权重或拷贝整套 node_modules。

候选阶段缩小到最大边 2048，细线/门洞回原分辨率局部处理；先测一个最小范围，不预生成全国/深圳全城瓦片。给 worker 设置项目缓存上限，记录删除对象列表，只清理自己生成且不再使用的中间文件。现有 Codespace 若没有 SSH 服务或依赖不兼容，按官方配置修正后再测试；本文未验证用户账号的 Codespace 列表或权限。
