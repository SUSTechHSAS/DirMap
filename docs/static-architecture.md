# DirMap static migration — implementation spec

Status: authoritative contract for the GitHub Pages migration. Written by the Lead.
Do not edit this file unless you are the Lead. Ask the Lead through `send_message` if the
contract is unclear or needs to change.

## 1. Goal and non-goals

Goal: the whole student/teacher web application must run from plain static files on GitHub
Pages. No HTTP API, no Python process, no server-side state.

- Build-time Python ("baker") converts the existing processed project data into static
  data files under `web/public/data/`.
- The browser loads those files, and performs route planning / navigation re-planning in
  TypeScript. The Python `dirmap` package becomes build-time tooling only.
- Teacher edits (targets, labels, terrain open/close strokes, published courses) persist in
  `localStorage`; "publishing" produces a downloadable release JSON plus on-device preview.
- No remote image recognition / OCR / auto-registration at runtime: those results are baked.
  Their buttons must be hidden or explained in the static build.
- The build must work from a sub-path (`https://<user>.github.io/<repo>/`). Never hard-code
  leading-slash URLs in application code; always go through `dataUrl()` / `BASE_URL`.

Non-goals: server parity for CP-SAT optimality proofs (JS uses exact DP where Python does,
otherwise a time-boxed heuristic labelled `FEASIBLE`), OCR/terrain re-analysis, manual
re-registration, uploading new map sheets.

### 5.5 BakedApproaches

The baker resolves, for every control whose role is `control`, the legal approach position
with `dirmap.access.AccessResolver.resolve(control, required_component=None)` against the
current graph (same graph as §5.6). Controls that fail are recorded as `ok: false` with the
Chinese `ValueError` message; the browser turns that into an unresolved plan item.

```ts
interface BakedApproaches {
  assetId: string; routingSchema: string; graphHash: string;
  controls: Record<string, BakedApproach>;
}
type BakedApproach =
  | { ok: true; node: number; pixel: [number, number]; local: [number, number];
      method: string; automatic: boolean; offsetM: number;
      lnglat: [number, number]; targetLnglat: [number, number] | null;
      featureKind?: string; reviewRequired?: boolean; targetPixel: [number, number] }
  | { ok: false; message: string };
```

`node` is an index into the baked graph node arrays (§5.6/5.7) and MUST stay consistent
with the baked node order (filtered quadtree order, see §7.2).

### 5.6 GraphMetadata (`maps/<id>/graph.json`)

```ts
interface GraphMetadata {
  assetId: string;
  schema: string;                // routing schema, e.g. "native-quadtree-v4-roof-palette"
  sourceHash: string;
  graphHash: string;             // python RasterGraph.content_hash
  step: 4; adaptive: true;
  width: number; height: number;
  nodeCount: number;
  directedEdgeCount: number;     // CSR nnz
  componentCount: number;
  costsPalette: number[];        // e.g. [0, 1, 1.5]
  expected: { lengthSum: number; weightSum: number; edgeCount: number };  // undirected pair count
  samples: { from: number; to: number; time: number; distance: number }[]; // golden Dijkstra results
}
```

`expected.lengthSum`/`weightSum` are `float64` sums of the per-edge `lengths`/`weights`
values (undirected edges, each edge counted once, in the CSR canonical order described in
§7.3). They are tolerance-checked by unit tests (`|a-b| <= 1e-6 * max(1,b)`).

### 5.7 GraphBundle binary (`graph.bin.gz`)

A single gzip stream (use the browser `DecompressionStream('gzip')`). After decompression:

| offset | type | value |
| --- | --- | --- |
| 0 | bytes | magic `DMGRAPH1` (8 bytes) |
| 8 | uint16 | format version = 1 |
| 10 | uint32 | width |
| 14 | uint32 | height |
| 18 | uint32 | nodeCount |
| 22 | uint16 | paletteCount |
| 24 | float32[paletteCount] | costsPalette |
| … | uint8[width*height] | costs, palette index per pixel, row-major |
| … | float32[nodeCount] | centre x of every quadtree cell (native pixel coords) |
| … | float32[nodeCount] | centre y |
| … | uint8[nodeCount] | cell size (1, 2 or 4) |
| … | uint8[nodeCount] | terrain value, index into costsPalette |

All values little-endian, no padding. Node pixels are the **filtered registration-valid**
quadtree leaves in the exact order Python's `_quadtree_graph` produced them: concatenated
by decreasing cell size (4, then 2, then 1), each class in row-major `np.nonzero` order,
after dropping the leaves whose `registration.forward(...)` is invalid (the mapping compacts
the owners exactly like the Python code). Verify this order: the JS-built graph must have
`nodeCount`, `directedEdgeCount`, `componentCount`, `lengthSum`, `weightSum` matching
`graph.json` within the tolerances above; `samples` must match within `1e-6` relative.

The browser reconstructs everything else:
1. `costs: Float32Array(width*height)` = `palette[index]`.
2. `local[i] = mesh.forward(pixel[i])` (registration mesh from `state.json`).
3. `owner: Uint32Array(width*height)` initialized to `0xffffffff`: for every node, fill its
   `size x size` block (`x0 = round(cx - (size-1)/2)`, likewise `y0`) with the node id.
4. Build edges exactly like `dirmap/graph.py::_quadtree_graph`:
   `for (dx,dy) of [(1,0),(0,1),(1,1),(-1,1)]` compare `owners[y,x]` with `owners[y+dy,x+dx]`
   over the valid slices, keep pairs with both owners valid and different; for diagonals also
   require `owners[y,x+dx]` and `owners[y+dy,x]` valid; key = `min*nodeCount + max`; unique
   keys sorted ascending; `a = key / nodeCount | 0`, `b = key % nodeCount`.
   `length = hypot(local[a]-local[b])`;
   `weight = length * (terrain[a]*size[a] + terrain[b]*size[b]) / (size[a] + size[b])`
   (compute the cost ratio with `Math.fround` rounding like numpy float32 intermediates;
   final multiply in float64). Store `lengths`/`weights` as `Float32Array` (accepting
   float32 storage rounding in the JS graph), `indices`/`indptr` as `Uint32Array`.
   Canonical CSR order: rows ascending, column indices ascending inside each row
   (scipy `coo_matrix.tocsr()` semantics; no duplicate entries).
   `expected.lengthSum/weightSum` are computed by the baker in exactly this canonical order.
5. Components via union-find over the CSR edges; `componentCount`.

## 6. Python baker (`tools/bake_static.py`)

Required behaviour:

- Read the processed project state from `data/projects/<id>/state.json` plus referenced
  `derived/...` artifacts (`store.artifact_path`). Copy `original.jpg` from the repository
  root files listed by `dirmap.store.catalog()`.
- Build the graph once per map with `dirmap.graph.build_graph(costs, Registration, sourceHash,
  edits, step=4)` and use it for everything (hash, approaches, samples, expected values).
- Compute `costsPalette` from `np.unique(costs)`; write `costs` as uint8 indices.
- Export the node arrays as in §5.7 (cell order as built by `_quadtree_graph`; note
  `graph.pixels` is float64 but values are exact halves, cast to float32 safely).

  `service._get_graph` does, with semantics from the `terrain.npz` arrays
  (`building`, `water`, `point_ink`, `vegetation`, `restricted`).
- Bake golden fixtures into `tests/fixtures/static/`:
  - `<asset>.dijkstra.json`: ~40 `{from,to,time,distance}` samples between node ids

  - `<asset>.matrix.json`: for a fixed scenario (all role=control and not rejected controls
    as targets, start/finish = the `start`/`start_finish` control's approach pixel or pixel),
    the resolved endpoint nodes, connector costs, full `(n+2)x(n+2)` matrix (as
    `matrix[i][j]` rounded to 1e-6), and `unresolved` messages. This is the primary golden

  - `optimizer.json`: exact-branch optimizer goldens. Build a valid matrix from one real

    (graph + plan_matrix + `dirmap.optimizer.solve` without saving state) and record

  - `release.json`-free: keep fixtures < 2 MB each.
- Also emit `release` (§5.4) and `releases.json`.
- Write `catalog.json` including `courseDefaults` from `data/course-presets.json`.
- Emit `reference.json` via `dirmap.reference.geojson(dirmap.service.reference())`.
- Emit `health.json` with a monthly WMM declination table via `pygeomag.GeoMag`
  for the Frame origin (2025-01-01 .. 2030-12-01, first of month).
- Copy the two legend files.
- Idempotent, fast (< 120 s), no writes outside the workspace, deterministic output
  (sorted keys / stable ordering, no timestamps except `generatedAt`).
- Add `--asset <id>` and `--skip-fixtures` flags for quick iteration.
- `tools/verify_static_data.py` must validate: JSON parse, binary header magic/version,
  array lengths, palette values, graph counters match `graph.json`, approaches node ids in
  range, release references exist, golden fixture files exist. Exit non-zero on failure.
  It must NOT need node.

export interface FrameInfo { crs: string; origin: Pixel }

### 7.2 raster-graph.ts

```ts
export interface GraphMetadata { ... §5.6 }
export class RasterGraph {
  static async load(assetId: string, state: MapState, opts?: { progress?: PlannerProgress }): Promise<RasterGraph>;
  readonly metadata: GraphMetadata;
  readonly width: number; readonly height: number; readonly step: number;
  readonly nodeCount: number;
  readonly pixels: Float64Array;   // 2*N
  readonly local: Float64Array;    // 2*N
  readonly costs: Float32Array;    // width*height
  readonly indptr: Uint32Array; readonly indices: Uint32Array;
  readonly weights: Float32Array; readonly lengths: Float32Array;
  readonly components: Uint32Array; readonly componentCount: number;
  snap(pixel: Pixel, maxDistancePx?: number): number;   // throws Error(Chinese) like python
  clearSegment(a: Pixel, b: Pixel): boolean;
  segmentPixels(a: Pixel, b: Pixel): Pixel[];           // §7.4 semantics
  dijkstra(sources: number[], metric: 'time'|'distance', targets?: number[]):
    { distances: Float64Array; predecessors: Int32Array }; // rows = sources
  shortestPath(from: number, to: number, metric: 'time'|'distance'): number[]; // A*, node path incl. endpoints
}
export function loadGraphBundle(buffer: ArrayBuffer): { metadata-independent arrays } // internal
```

- `load()` fetches `mapDataUrl(assetId, 'graph.json')` and `graph.bin.gz` through the
  Lead-owned `web/src/data.ts` helpers (`dataUrl('maps/<id>/graph.bin.gz')`), decompresses
  with `DecompressionStream('gzip')`, then builds the graph as §7.3. Progress strings:
  `载入通行图 20%`, `建立保留细墙的通行图 60%`, `完成通行图 90%`.
- `snap` must reproduce `RasterGraph.snap`/`node_at` semantics using the owner grid
  (exact owner lookup at the rounded pixel first, then rings up to `maxDistancePx`, with
  `clearSegment` checks; fall back to nearest clear candidate over node centres within the
  radius). Error message: `点位没有无障碍连接，请在同一侧选择实际可到达的位置`.
- `dijkstra` returns predecessor rows for the requested sources (only allocate what is
  needed; callers use `targets` to stop early when all targets are settled). For
  `metric='time'` use `weights`, for `'distance'` use `lengths`.
- `shortestPath` is A* with the Euclidean local-metre heuristic (admissible and consistent);
  used by route expansion. Cache nothing global beyond the graph.
- `segmentPixels` must reproduce `dirmap/graph.py::segment_pixels` including half-pixel
  boundaries and one-pixel-thick wall/corner checks (this drives `clearSegment`).
- Deterministic node order and edge order as specified in §5.7 — golden tests enforce it.

### 7.3 optimizer.ts

Port `dirmap/optimizer.py::solve` and its helpers to TypeScript, producing the same
`{status, routes, coverage, proof}` object (plus the same Chinese error messages and
validation rules):

- `subset_tours` → Held-Karp for all_visit `n <= 13`, fixed start/finish (matrix index 0 /
  n+1), optional `mandatoryOrder` constraints for mixed mode.
- `assign_subsets` → two-stage DP for `split_coverage` (`n <= 10`) and `mixed_coverage`
  (`n <= 13` and `n - mandatory <= 9`), including `min_max_finish_then_sum`,
  `min_total_time`, `min_distance`, staggered departures and service times.
- Fallback (all other cases): greedy insertion + 2-opt + relocation, time-boxed by
  `timeLimit` (default 5 s), returning `status: 'FEASIBLE'`,
  `proof.algorithm: 'insertion_2opt_relocation'`, `proof.globalOptimalityProven: false`,
  `proof.bestBound: null`, `proof.relativeGap: null` and the same `proof.scope` text as
  Python. Do not port CP-SAT. Exact branches must match Python exactly (same order arrays).
- Validate final coverage/order exactly like Python (`每队必到与全班分担规则` errors).
- Performance target: exact branches < 2 s in node for the real fixtures.

### 7.4 planner.ts

```ts
export interface PlannerProgress { (percent: number, message: string): void }
export interface Planner {
  readonly graphHash: string;
  plan(request: PlanRequest, controls: Control[], progress?: PlannerProgress): Promise<Plan>;
  navigate(release: StaticRelease, request: NavigationRequest, controls: Control[]): Promise<NavigateResponse>;
}
export async function getPlanner(state: MapState, progress?: PlannerProgress): Promise<Planner>;
export function clearPlannerCache(): void;
```

- `getPlanner` caches by `${assetId}:${version}`; loads `RasterGraph` + `approaches.json`
  (`dataUrl('maps/<id>/approaches.json')`). If `state.edits.length` differs from the baked
  state, the caller (Lead) will pass a bumped version, so one cache entry per edited
  version is fine; reconstruct the graph with the edits applied to `costs` first
  (circle/polyline rasterization approximating cv2: fill pixels within `radiusPx` of the
  polyline with `close -> 0`, `open -> cost`), then use graphHash
  `${bakedHash}-e${shortHashOfEdits}` (16 hex chars of a simple string hash).
- `plan(request, controls, progress)` replicates `service.plan_course` + `plan_matrix` +
  `expand_route` + `solve` and returns exactly the `Plan` object (§8.2) with fields:
  `id` (16 hex, crypto random), `assetId`, `request`, `routingSchema` (`state.routingSchema`
  or `__DIRMAP_ROUTING_SCHEMA__`), `status`, `unresolved`, `routes`, `graphHash`, `version`,
  `approaches`, `draft`, `createdAt`, `coverage`, `proof`, `graphStatistics`,
  `preparationSec`, `planningElapsedSec`. Verify mandatory/objective/mode validation and
  throw the Python Chinese messages.
- `planMatrix` logic: for each control use the baked approach when available
  (`ok:true` → node/pixel/local from the entry; `ok:false` → unresolved with its message;
  no entry and no `approachPixel` → fall back to `graph.snap(control.pixel)`); if
  `control.approachPixel` is set (teacher-confirmed), snap it with `maxDistancePx=4` and
  treat as `method: 'manual', automatic: false`. start/finish: `graph.snap(pixel)`;
  validate component equality (message like Python `位于独立通行区域（N 个节点）…`).
  Connectors: `hypot(localEndpoint - graph.local[node])`, factor = `graph.costs[ry*width+rx]`,
  connectorWeights = connectors * factors (time metric) or connectors (distance metric).
  Matrix = `dist[a][b] + connector[a] + connector[b]`, diagonal 0.
- `expandRoute` replicates `graph.expand_route`: for each consecutive pair in `order`,
  A* path, positions = `[world[a], ...local[path], world[b]]`, accumulate distance and
  travelWeight, produce `geometry` (lnglat via `frameLngLat`), `localGeometry`,
  `distanceM`, `travelWeightM`, `nodeIds`, `edgeIds`, `legs` (`fromId/toId/startIndex/
  endIndex/distanceM`).
- `navigate(release, request)` replicates `service.navigate_course`: accuracy <= 20 m,
  timestamp within -5 s / +20 s of `Date.now()`, team exists, completed ids must be a
  prefix, recompute plan matrix for remaining controls from the current pixel + published
  finish, return `{status:'READY', version, graphHash, completedControlIds, generatedAt,
  route, scope}` or `{status:'NEEDS_REVIEW', unresolved, version, graphHash, route: null}`.
  Throw Chinese messages for all other failures (`队伍不属于这份课程`,
  `已完成点必须按本队课程顺序记录，不能跳过必到点`, `定位精度不足，请移至开阔处后重试`,
  `定位已过期，请等待新的定位样本`, `当前位置超出已校准的课程范围`, …).
  Timestamp semantics: the Lead passes `timestampMs`/`accuracyM` straight from
  `GeolocationPosition`; `timestamp` there can be epoch ms (it is on modern browsers).
- No network beyond `fetch` of static files; no `localStorage` inside planner.

## Addendum A — approved contract updates (Lead, after implementation questions)

1. **Approaches are canonical-start aware (supersedes the plain `resolve(None)` rule in §5.5).**
   The baker resolves with `required_component=None` first; if the returned node's component
   differs from the component of the canonical start/finish node, it re-resolves with
   `required_component=start_component`. This reproduces what Python's `plan_matrix` does for
   the built-in start/finish symbol (e.g. szu-1 c6 becomes usable; szu-2 keeps its exact
   unresolved messages). The baker additionally writes:
   `startPixel`, `finishPixel`, `startNode`, `startComponent`, `note`, and a per-entry
   `component` field for `ok:true` approaches. The JS planner: if a baked approach's
   `component` differs from the start component of the current request, return unresolved
   `合法到访侧与起点不连通，请核对通道`.
2. **Edited graphs (local `state.edits`) are rebuilt in the browser.** Node ids change, so
   the planner must not reuse baked `node`/`local` values: it re-resolves each approach with
   `snap(bakedApproach.pixel, maxDistancePx=4)` (and teacher `approachPixel` the same way),
   recording unresolved `合法到访侧与起点不连通，请核对通道` (automatic) /
   `指定到访位置不可达，请核对门洞和到访侧` (manual) on failure. Blocked pixels must never
   be opened. Graph hash for edited graphs: `${bakedHash}-e${16 hex}`.
3. **Navigation validation:** before re-planning, `navigate()` compares
   `release.plan.graphHash` with the loaded graph hash and throws
   `课程通行图与当前静态构建不一致，无法重新规划（本机通行修正不会随课程分发）` when they
   differ (edited-graph local releases cannot be shared), and
   `课程已更新，请使用教师提供的新课程链接` for superseded/schema-mismatched releases.
4. **Types:** `web/src/types.ts` now carries optional `Plan.createdAt/preparationSec/
   planningElapsedSec/graphStatistics`, expanded `Plan.proof` fields,
   `Route.travelWeightM/nodeIds/edgeIds`, and optional
   `MapState.routingSchema/graphHash/review/static`; the planner returns structural objects
   with those fields (no casts needed). `plan.routingSchema` comes from
   `graph.metadata.schema`; never reference `__DIRMAP_ROUTING_SCHEMA__` at module scope in
   modules that must also run under `node --experimental-strip-types`.
5. **`getPlanner(state, progress?, assets?)`**: the third `assets` argument is a test-only
   seam `{ metadata, buffer, approaches }` so node unit tests can build a planner from
   `web/public/data` via `node:fs`; the public two-argument contract used by `main.ts` is
   unchanged and `web/src/data.ts` stays browser-only.
6. **Deterministic bake:** `catalog.generatedAt` and `health.modelDate` are derived from
   `max(updatedAt)` of the source states, so repeated bakes are byte-identical. pygeomag is
   called with `allow_date_outside_lifespan=True`; the final months of the declination table
   are extrapolated beyond the WMM-2025 5-year lifespan (documented in DEPLOY.md).
7. **Service worker:** graph bundles (`data/maps/<id>/graph.json`, `graph.bin.gz`,
   `costs`-adjacent data) are deliberately not precached/intercepted; only course JSON,
   overlay PNG and `health`/`reference`/`releases.json` use the offline cache.
